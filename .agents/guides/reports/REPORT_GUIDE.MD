# 🤖 Инструкция для агента: генерация отчётов к Pull Request

Эта инструкция описывает, что именно агент должен сделать при получении задачи сформировать отчёты по ветке. Агент создаёт **два файла** — основной PR-отчёт и приложение к нему — строго по соответствующим гайдам.

## Используемые гайды

| Гайд | Описание |
|------|----------|
| [PR_REPORT_GUIDE.MD](PR_REPORT_GUIDE.MD) | Структура основного PR-отчёта |
| [PR_BRANCH_REPORT_GUIDE.MD](PR_BRANCH_REPORT_GUIDE.MD) | Структура приложения к PR |
| [GIT_GUIDE.MD](../git/GIT_GUIDE.MD) | Просмотр изменений ветки через git |

---

## Входные данные

Перед началом работы агенту необходимо знать:

- **Имя feature-ветки** — например, `feat/comments`
- **Имя базовой ветки** — например, `dev` или `main`
- **Номера и названия задач YouGile**, которые закрывает PR

---

## Шаг 1. Сбор данных из git

Для сбора информации об изменениях ветки используй **[GIT_GUIDE.MD](../git/GIT_GUIDE.MD)**.

Минимальный набор для генерации отчётов:
- Список коммитов — `git log <base>..<feature> --oneline`
- Статистика изменённых файлов — `git diff <base>...<feature> --stat`

По умолчанию базовая ветка — `dev`. Полный порядок выполнения команд, синтаксис и примеры описаны в GIT_GUIDE.

---

## Шаг 2. Создание двух файлов

По собранным данным создай два файла. Все отчёты помещаются в директорию **`.agents/reports/`** (от корня репозитория).

Имена файлов строятся по шаблону:

```
.agents/reports/<имя-ветки>_pr.md
.agents/reports/<имя-ветки>_branch.md
```

Пример для ветки `feat/comments`:

```
.agents/reports/feat-comments_pr.md
.agents/reports/feat-comments_branch.md
```

> Слэш `/` в имени ветки заменяй на дефис `-`. Если директория `.agents/reports/` не существует — создай её.

---

## Файл 1: `<имя-ветки>_pr.md` — основной PR-отчёт

Заполняй строго по `PR_REPORT_GUIDE.md`. Структура:

```markdown
## Тип:
- <тип>

## Описание
- [x] <одна строка на каждую задачу YouGile>

## Ссылки на YouGile
<ссылки в том же порядке, что пункты описания>

## Скриншоты изменений
_Скриншоты будут добавлены вручную._

## Дополнительно
<если есть — заполни; если нет — убери раздел>
```

### Правила заполнения:

**Тип** — выбери из таблицы в гайде. Если изменения затронули несколько типов — перечисли все.

**Описание** — количество пунктов строго равно количеству задач YouGile. Один пункт = одна задача. Всё сделанное в рамках задачи ужимается в одну строку. Пиши в прошедшем времени, конкретно: указывай эндпоинты, компоненты, модели — только те, что реально есть в проекте.

**Ссылки** — порядок ссылок совпадает с порядком пунктов в описании.

**Скриншоты** — агент не может прикладывать изображения. Оставь плейсхолдер: `_Скриншоты будут добавлены вручную._`

**Дополнительно** — если в ходе анализа коммитов или diff-а обнаружены изменения, не привязанные к задачам (новые переменные окружения, необходимые ручные действия после мержа, временные решения, зависимости от других веток) — опиши их здесь. Если ничего такого нет — раздел не добавляй.

## Файл 2: `<имя-ветки>_branch.md` — приложение к PR

Заполняй строго по `PR_BRANCH_REPORT_GUIDE.md`. Структура:

```markdown
# Отчёт по ветке `<feature>`

**Задача YouGile:** [MO-X](ссылка) — краткое название задачи.

---

## Заголовок Pull Request

<одна строка — текст для поля Title PR на GitHub>

---

## Краткая сводка

<2–4 предложения: что реализовано, какие слои затронуты, есть ли нестандартные решения>

## Ключевые коммиты

| Хэш | Описание |
|-----|----------|
| `xxxxxxx` | ... |

---

## Backend

- ...

---

## Frontend

- ...
```

### Правила заполнения:

**Заголовок Pull Request** — перед «Краткой сводкой» добавь раздел; под ним **только одна строка** — текст для поля Title PR на GitHub. Пояснения и запреты (в т.ч. не дублировать Title в файле `_pr.md`) описаны в `PR_BRANCH_REPORT_GUIDE.md` и **в файл отчёта по ветке не копируют**.

**Краткая сводка** — общая картина, не перечисление коммитов. Что сделано в целом, что необычного.

**Ключевые коммиты** — хронологический порядок от старых к новым. Берёшь из `git log`, переворачиваешь порядок. Близкие по смыслу коммиты группируй в одну строку через `…`. Хэш — первые 7 символов.

**Backend / Frontend** — добавляй только те разделы, которые реально есть в изменениях. Определяй по путям файлов из `git diff --stat`: файлы в `src/` (NestJS-модули, контроллеры, сервисы, Prisma-схема) — backend; файлы в `client/` или `frontend/` (компоненты, страницы, хуки, query-файлы) — frontend.

Перечисляй только реальные сущности проекта: модули, сервисы, контроллеры, модели Prisma, компоненты, страницы, хуки. Не используй термины, которых нет в проекте.

---

## Итог

После выполнения агент должен выдать два готовых файла:

| Файл | Содержимое |
|------|------------|
| `<имя-ветки>_pr.md` | Основной PR-отчёт: тип, описание, ссылки, скриншоты, дополнительно |
| `<имя-ветки>_branch.md` | Приложение: заголовок PR (только Title), сводка, коммиты, backend, frontend |
