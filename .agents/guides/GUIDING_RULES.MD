# Правила оформления гайдов

Этот документ устанавливает единые требования к структуре всех гайдов в директории `.agents/guides/`.

---

## Блок используемых гайдов

В начало каждого гайда, **перед основным содержимым**, добавляется блок со ссылками на все гайды, которые используются или упоминаются в данном документе.

### Формат блока

```markdown
## Используемые гайды

| Гайд | Описание |
|------|----------|
| [НАЗВАНИЕ](relative/path/TO_GUIDE.MD) | Краткое описание |
```

### Правила

- Блок размещается **сразу после заголовка** (`# ...`) и вводного абзаца, **до первого `---`**.
- В таблицу включаются только те гайды, которые **реально используются** в тексте (на которые есть явные ссылки или отсылки).
- Если гайд ни на что не ссылается — блок не добавляется.
- Пути — **относительные** от расположения текущего файла.
- Названия ссылок совпадают с именем файла гайда (без расширения или с `.MD`/`.md`).

### Пример

Файл `guides/reports/REPORT_GUIDE.MD` ссылается на гайды из той же папки и из `guides/git/`:

```markdown
## Используемые гайды

| Гайд | Описание |
|------|----------|
| [PR_REPORT_GUIDE.MD](PR_REPORT_GUIDE.MD) | Структура основного PR-отчёта |
| [PR_BRANCH_REPORT_GUIDE.MD](PR_BRANCH_REPORT_GUIDE.MD) | Структура приложения к PR |
| [GIT_GUIDE.MD](../git/GIT_GUIDE.MD) | Просмотр изменений ветки через git |
```

---

## Язык и формат

- Все гайды пишутся в формате **Markdown** (`.MD` или `.md`).
- Заголовки используют `#`, `##`, `###` — без пропусков уровней.
- Примеры команд оформляются в блоки ` ```bash ` или ` ```typescript `.
- Имена файлов, путей и команд — в инлайн-коде `` `вот так` ``.
