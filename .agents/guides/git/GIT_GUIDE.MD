# Руководство для агента: просмотр изменений текущей ветки

Этот документ описывает, как агент должен собирать информацию об изменениях в ветке, не читая весь проект целиком. Применяется при составлении отчётов, генерации кода на основе изменений, анализе PR.

---

## Базовая ветка для сравнения

По умолчанию все сравнения выполняются относительно ветки **`dev`**.

> Если пользователь явно указал другую базу (ветку, тег или хэш коммита) — используй её вместо `dev`. Примеры: `main`, `a3f91bc`, `v2.1.0`.

В командах ниже `<base>` — базовая ветка (по умолчанию `dev`), `<feature>` — текущая ветка (можно подставить `HEAD`).

---

## Шаг 1. Узнать имя текущей ветки

```bash
git branch --show-current
```

Запомни результат — он понадобится как `<feature>` во всех последующих командах.

---

## Шаг 2. Список коммитов ветки

```bash
git log <base>..<feature> --oneline
```

**Пример:**
```bash
git log dev..HEAD --oneline
```

Выводит все коммиты, которые есть в `<feature>`, но отсутствуют в `<base>`. Используй для понимания истории изменений и при составлении раздела «Ключевые коммиты».

> Синтаксис `..` (две точки) — для `git log`.

---

## Шаг 3. Список затронутых файлов

```bash
git diff <base>...<feature> --name-only
```

**Пример:**
```bash
git diff dev...HEAD --name-only
```

Выводит только пути файлов без содержимого. Используй как карту изменений, чтобы точечно читать только нужные файлы, а не весь проект.

> Синтаксис `...` (три точки) — для `git diff`.

---

## Шаг 4. Статистика по файлам

```bash
git diff <base>...<feature> --stat
```

**Пример:**
```bash
git diff dev...HEAD --stat
```

Показывает каждый изменённый файл с количеством добавленных (`+`) и удалённых (`-`) строк. Помогает быстро оценить масштаб изменений и выделить ключевые файлы.

---

## Шаг 5. Полный diff (при необходимости)

```bash
git diff <base>...<feature>
```

**Пример:**
```bash
git diff dev...HEAD
```

Выводит полное содержание всех изменений. Используй только если нужен детальный анализ кода. Для крупных веток предпочти читать конкретные файлы из списка шага 3.

### Diff конкретного файла

```bash
git diff <base>...<feature> -- <path/to/file>
```

**Пример:**
```bash
git diff dev...HEAD -- src/comments/comment.service.ts
```

Позволяет изучить изменения в одном файле, не загружая весь diff.

---

## Шаг 6. Diff конкретного коммита

```bash
git show <hash>
```

**Пример:**
```bash
git show a3f91bc
```

Выводит изменения одного коммита. Используй, если в `git log` нашёлся коммит, который нужно изучить подробнее.

---

## Рекомендуемый порядок работы

1. Получить имя текущей ветки (`git branch --show-current`).
2. Получить список коммитов (`git log <base>..<feature> --oneline`).
3. Получить список изменённых файлов (`git diff <base>...<feature> --name-only`).
4. По списку файлов определить, какие из них нужно читать (через Read), — не читать весь проект.
5. При необходимости — посмотреть diff конкретного файла или коммита.

> Такой порядок минимизирует объём читаемого кода и ускоряет работу агента.

---

## Справка по синтаксису

| Синтаксис | Команда | Поведение |
|-----------|---------|-----------|
| `A..B`    | `git log` | Коммиты в B, которых нет в A |
| `A...B`   | `git diff` | Diff B относительно точки ветвления от A |

---

## Примеры для нестандартных случаев

### Сравнение с конкретным коммитом

```bash
git log a3f91bc..HEAD --oneline
git diff a3f91bc...HEAD --stat
```

### Сравнение с тегом

```bash
git log v2.1.0..HEAD --oneline
git diff v2.1.0...HEAD --name-only
```

### Сравнение с другой веткой (не dev)

```bash
git log main..HEAD --oneline
git diff main...HEAD --stat
```
