## Правка N2 — Добавлена `db:recreate`

Новая команда `npm run db:recreate` — полный пересоздание БД с нуля из текущей схемы.

Когда нужна: при изменениях `schema.prisma`, когда проще сбросить всё и начать заново, чем писать инкрементальную миграцию (только во время разработки, **никогда на продакшне**).

Что делает внутри (по шагам):

1. `prisma validate` — проверяет что схема корректна (чтобы не ломать БД с битой схемой)
2. Удаляет папку `prisma/migrations` — стирает историю миграций
3. `prisma migrate reset --force` — дропает и пересоздаёт базу (без подтверждения)
4. `prisma migrate dev --name init` — создаёт свежую миграцию «init» из текущей схемы
5. `prisma generate` — пересобирает Prisma Client

```bash
npm run db:recreate
```

## Минимальный набор команд для работы

### Первый запуск (один раз)

```bash
# 1. Скопировать файл окружения и заполнить своими значениями
cp .env.example .env

# 2. Поднять базу данных в Docker
docker compose up -d postgres

# 3. Установить зависимости
npm run install:all

# 4. Применить миграции к базе данных
npm run db:migrate

# 5. (опционально) Сгенерировать Prisma-клиент, если не сделалось автоматически
npm run db:generate
```

### Ежедневная разработка

```bash
# Убедиться что Postgres запущен
docker compose up -d postgres

# Запустить всё (бек + фронт + типы) одной командой
npm run dev
```

Или по отдельности:
```bash
npm run dev:back    # только бекенд
npm run dev:front   # только фронтенд
```

### Работа с базой данных

```bash
npm run db:migrate   # создать и применить миграцию (после изменения schema.prisma)
npm run db:generate  # пересобрать Prisma-клиент
npm run db:studio    # открыть визуальный редактор БД в браузере
npm run db:recreate  # СБРОС: удалить миграции, пересоздать БД, новая init-миграция
```

### Деплой

```bash
docker compose up -d          # поднять всё в Docker
npm run db:deploy              # применить миграции на продакшне
```
